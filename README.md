# 案例 001 · AI 办公流水线

## 展示路径

1. 「现在乱在哪」：多渠道消息、会议资料、表格数字分散。
2. 「错了会怎样」：日期承诺错误、无人负责、重复行抬高数字。
3. 观众选择场景并改动虚构输入，逐步或自动播放输入→清洗→分工→质检→交付。
4. 人工复核后确认交付，查看输出区与知识库新增结果。

所有业务记录均为虚构。原始培训课件、真实项目材料和个人数据不进入公开仓库。

## 文件

- `web/`：演示页面、脚本、样式、卡通素材。
- `server/index.js`：公网访问的服务端账号密码验证、会话 Cookie 和尝试次数限制。
- `scripts/build.mjs`：把页面资源打包入 Worker；不写入密码。
- `check.mjs`：验证演示交互。
- `check-auth.mjs`：验证未登录拦截、登录、退出和限流。
- `.openai/hosting.json`：本地 Sites 项目标识，不同步到公开 GitHub。

## 本地验证

```sh
node scripts/build.mjs
node check.mjs
DEMO_PASSWORD='<本地测试密码>' node check-auth.mjs
```

正式站点使用 Sites 运行时 Secret `DEMO_PASSWORD`、`SESSION_SECRET`。公开仓库不保存密钥。构建产物 `dist/` 不提交到公开仓库。

## 访问边界

公网 URL 可打开登录页，页面和 JS 均由 Worker 在验证会话后返回。账号 `demo` 的共享密码只适用于虚构演示；知道密码的人都能进入，无法凭共享密码区分具体员工。当前失败尝试限制按 Worker 实例计数，不保证跨实例或多 IP 的全局封禁。未来若接入真实数据，先换成可识别个人的登录与持久化限流。
